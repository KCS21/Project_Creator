## 2. 배포 (10분)

### 방법 A — GitHub 저장소에 올려 자동 배포 (Netlify가 저장소와 연결된 경우)

**v1은 파일 1개였지만 v2는 파일 6개 + 함수 폴더입니다. `index.html`만 바꾸면 화면이 비어 버립니다.** 아래를 전부 올려야 합니다.

```
index.html        ← 기존 파일을 덮어씀
styles.css        ← 새 파일
app.js            ← 새 파일
ai-catalog.js     ← 새 파일
netlify.toml      ← 새 파일
netlify/          ← 새 폴더 (안에 functions/gemini.mjs)
```

브라우저만으로 하는 절차:

1. github.com에서 해당 저장소를 연다
2. **Add file → Upload files**
3. 탐색기에서 `pipeline-builder-v2` **폴더를 열고, 그 안의 6개 항목을 전부 선택**해 페이지로 끌어다 놓는다
   - ⚠ `pipeline-builder-v2` 폴더 자체를 끌어다 놓으면 저장소 안에 하위 폴더가 생겨 사이트가 뜨지 않는다. **폴더를 열고 안의 내용물**을 올릴 것
   - `netlify` 폴더는 통째로 끌어다 놓으면 하위 구조가 그대로 유지된다
4. 커밋 메시지를 적고 **Commit changes**
5. Netlify가 자동으로 재배포한다 (Deploys 탭에서 진행 상황 확인)

그다음 **Site configuration → Environment variables**에서 아래 3번 표대로 `GEMINI_API_KEY`를 넣고, **Deploys → Trigger deploy → Clear cache and deploy site**를 한 번 실행한다.

> 웹 업로드로는 파일 삭제가 안 된다. 저장소에 남아 있는 옛 파일(app.py, requirements.txt 등)은 그대로 남는데, 정적 사이트라 동작에는 지장이 없다. 다만 **저장소에 올라간 파일은 누구나 내려받을 수 있으므로** 실제 API 키가 적힌 파일이 없는지는 확인할 것. 빌드가 실패하면 남아 있는 `requirements.txt`·`package.json` 때문일 수 있으니 그때 지운다.

**이후 카탈로그 갱신은 훨씬 간단해집니다.** github.com에서 `ai-catalog.js`를 열고 연필 아이콘 → 수정 → Commit 하면 Netlify가 알아서 재배포합니다. 내려받고 올리고 할 필요가 없습니다.

### 방법 B — Netlify에 폴더 통째로 올리기 (GitHub을 안 쓰는 경우)

1. https://app.netlify.com 로그인 → **Add new site → Deploy manually**
2. `pipeline-builder-v2` 폴더를 통째로 드래그
3. 배포 후 **Site configuration → Environment variables**에서 아래를 추가

| 변수명 | 필수 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | ✅ | https://aistudio.google.com 에서 발급한 키 |
| `DAILY_LIMIT` | | IP당 하루 허용 횟수. 미설정 시 15 |
| `DEMO_PASSCODE` | | 설정하면 이 암호를 아는 사람만 서버 데모 사용 가능 |
| `ALLOWED_ORIGIN` | | 지정한 도메인에서 온 요청만 허용 (예: `https://example.netlify.app`) |

4. 환경변수를 넣은 뒤 **Deploys → Trigger deploy → Clear cache and deploy site** 한 번 실행

> 환경변수를 넣지 않아도 앱은 동작합니다. 다만 "서버 데모" 모드가 막히고, 사용자가 자기 키를 넣는 모드만 쓸 수 있습니다.

### 방법 B — 기존 사이트를 v2로 교체

기존 Netlify 사이트의 **Deploys → Deploy manually**에 이 폴더를 드래그하면 같은 주소로 교체됩니다.
이 기회에 **Site configuration → Change site name**에서 주소 오타(`procject` → `project`)도 함께 고치십시오.

### 로컬에서 먼저 보기

`index.html`을 브라우저로 바로 열면 됩니다(서버 데모는 안 되고 내 키 모드만 동작).
함수까지 함께 시험하려면 `npm i -g netlify-cli` 후 폴더에서 `netlify dev`.

## 4. v1에서 고친 것

| # | v1 문제 | v2 처리 |
|---|---|---|
| 1 | `maxOutputTokens` 미설정 → 응답 잘리면 그냥 "오류" | 토큰 상한 명시 + `finishReason: MAX_TOKENS` 감지 → 압축 지시를 붙여 자동 1회 재시도 |
| 2 | JSON 형식 미보장 | `responseSchema`로 구조 강제. 스키마가 거부되면 프록시가 스키마 없이 1회 재시도 |
| 3 | 키가 틀려도 모델 3개를 다 호출 | 400·401·403은 즉시 중단하고 원인별 안내, 429는 "한도 초과"로 분리 |
| 4 | 흐름도에서 모델 출력이 escape 없이 innerHTML로 들어감 | 모든 출력이 `textContent`. 인라인 스크립트·`onclick`을 없애고 CSP로 이중 차단 |
| 5 | 키를 localStorage에 무기한 저장하며 "안전하게 보관" 문구 | 저장 여부를 사용자가 선택(기본은 탭 닫으면 소멸), 삭제 버튼, 정확한 문구로 교체 |
| 6 | 주소 오타 `procject` | 배포 시 사이트 이름 변경 안내 (위 2번) |
| 7 | 모델 목록 하드코딩 | `CONFIG.modelCandidates` 한 곳으로 모으고, 실행 시 ListModels로 실제 사용 가능 모델을 확인해 자동 보정 |
| 8 | 폴더 위생 | 아래 5번 참고 |

추가로 **6단계 고정을 해제**(3~8단계 가변)하고, 단계마다 난이도·예상 소요시간·리스크·대안 도구를 붙였으며, 계획 저장(내 계획 탭)과 체크 진행률을 넣었습니다.

## 6. 카탈로그 유지보수 (가장 중요)

이 앱의 품질은 `ai-catalog.js` 하나에 달려 있습니다. 모델이 도구를 기억해서 답하는 게 아니라,
**이 파일에 있는 도구만 고르고 이름·URL·요금은 앱이 직접 채워 넣기 때문**입니다.

- **분기마다 한 번** 각 도구의 공식 페이지에서 `status` / `free` / `url`을 확인하고 `AI_CATALOG_META.verified` 날짜를 갱신하십시오.
- 90일이 지나면 화면 우상단에 "확인 필요"가 자동으로 표시됩니다.
- `status`를 `'ended'`로 바꾸면 추천에서 자동 제외되고 도감에만 남습니다. 삭제하지 말고 종료 사유를 `caution`에 적어 두는 편이 낫습니다. 수강생·고객에게 "이건 없어졌다"를 알려주는 것도 정보입니다.
- 도구를 추가할 때는 `id`(영문 소문자·하이픈)만 겹치지 않게 하면 됩니다. 나머지는 자동으로 화면과 프롬프트에 반영됩니다.

현재 카탈로그: **2026-09-05 확인 기준**, 국내 25개 + 해외 37개 + Google 15개 + 종료된 서비스 4개.
요금·무료한도가 공식 페이지에서 확인되지 않은 항목은 `'미확인'`으로 두었고, 추천 후보에서 자동 제외됩니다.

## 7. 문제가 생겼을 때

**"Request contains an invalid argument." (400)**
API가 요청의 일부를 거부한 것입니다. 앱이 자동으로 요청 방식을 세 단계로 낮춰 재시도합니다.

1. `구조화 스키마` — 응답 형식을 스키마로 강제 (품질 최고)
2. `JSON 모드` — JSON만 받고 형식은 프롬프트로 지시
3. `일반 모드` — 아무 제약 없이 받아 본문에서 JSON을 추출

세 단계 중 하나가 통하면 그 방식을 기억해 다음부터는 바로 씁니다(탭을 닫으면 초기화). 세 단계 모두 거부되면 오류 상자 안의 **"API가 보낸 원문"**을 펼쳐 보십시오. 어느 필드가 거부됐는지 나옵니다. 성공한 방식은 결과 상단 배지에도 표시됩니다.

**로컬에서 열었더니 "서버 데모에 연결하지 못했습니다"**
`file://`로 열면 서버 함수가 없어 정상입니다. 이때는 자동으로 "내 API 키" 모드로 고정됩니다.

**바꾼 게 반영되지 않음**
브라우저가 이전 `app.js`를 캐시한 것입니다. `Ctrl+Shift+R`로 강제 새로고침하십시오.

## 8. 알려진 한계

- **정부 지원사업 목록은 연간 공고제**라 가장 빨리 낡습니다. 2026년 주요 사업은 이미 마감되었고, 상태 문구를 직접 갱신해야 합니다.
- 서버 데모의 사용량 제한은 Netlify Blobs를 쓸 수 있으면 정확하고, 없으면 함수 인스턴스 메모리 기준이라 느슨합니다. 정확한 제한이 필요하면 Blobs 활성화를 확인하십시오.
- 생성 결과는 **초안**입니다. 도구 선택은 카탈로그에 묶여 있어 안전하지만, 단계 구성과 프롬프트 내용은 사람이 검토해야 합니다.
